# G304 강의실 수집 — 2026-09-17

사용자 확인에 따라 2026-09-17 변경 전에 수집한 CSI는 모두 **G308 강의실** 데이터다.
오늘은 **G304**에서 **0명 → 1명 → 2명 → 3명 → 4명** 순서로 수집한다.
추가 지시에 따라 이전 [수집 계획](csi_collection_0to5_plan.md)의 행동 규칙을 적용하면서,
**1명 이상은 한 번 실행해 동작당 5분씩 연속 수집**한다. 기본은 앉기 5분 → 서기 5분 →
교대 걷기 5분을 2회 반복하는 **인원별 30분**이다. 반복 횟수와 동작당 시간은 입력으로 변경한다.
오늘 인원 범위는 0~4명이며 이전 0~5명 12시간 계획 전체를 오늘 실행하는 것은 아니다.

목표는 여러 환경에서 학습한 모델이 새 강의실의 **0명 기준 CSI만으로 환경을 보정한 뒤
인원수를 추정**할 수 있는지 검증하는 것이다. 현재 구현한 기능은 강의실·배치·행동 라벨과
0명 기준 세션의 연결이다. 빈 방 보정 모델, 강의실 자동 식별, 새 방의 인원 추정 성능은
아직 구현·검증 완료된 결과가 아니다.

## RX 실행과 입력

열려 있던 RX 실행기를 종료하고 바탕화면 **CSI RX 수집** 아이콘을 새로 연다.
아이콘은 현재 프로젝트의 수정된 코드를 직접 실행하므로 재설치가 필요 없다.
터미널에서는 다음 명령을 사용한다.

```bash
python3 tools/csi_capture_rx_launcher.py
```

첫 번째 빈 방 수집:

```text
[0] 수집 강의실 ID: G304
[1] 수집 인원 수: 0
[1-1] 배치 ID: A
[2] 현재 Wi-Fi 확인
[3] 수집 시간(분): 5  (Enter 기본값)
[4] 카메라: Y
[4-2] 퇴실·자리 준비 시간(초): 30
[4-3] 안정화 시간(초): 60
```

0명은 동작 전환 없이 입력한 시간 내내 빈 방을 유지한다. 기본 시간은 5분이며 더 오래
수집하려면 `[3]`에 20 또는 30 등을 입력한다. 준비·안정화 90초는 CSI 수집 시간에 포함되지 않는다.

강의실은 매번 직접 입력한다. Enter만 입력하면 다시 물어보며 `g304`는 `G304`로 통일한다.
빈 방은 행동 `empty`, 기준 세션 ID는 자기 자신의 ID로 저장한다. 완료 여부는 별도 기록한다.
실패한 0명 파일은 후속 수집의 기준 후보로 제시하지 않는다.

이후 인원을 1·2·3·4로 바꾸며 각 파일을 새로 수집한다. 강의실 `G304`, 같은 배치 `A`를
입력하고 행동을 선택한다. 같은 강의실·배치에서 완료된 0명 세션이 있으면 목록에서 고른다.
기본 선택은 가장 최근 세션이며, `0`을 고르면 연결을 보류한다. 후보가 없을 때도 미연결로
수집할 수 있으므로 오늘은 반드시 0명 수집 완료와 저장을 먼저 확인한다.

후보 목록의 `needs_review`는 추가 품질 검수가 필요하다는 뜻이다. 기준 세션 연결이
영상 검수·퇴실 구간 확인·학습 허용 판정을 대신하지 않는다. G308의 빈 방을 G304 기준으로
자동 연결하지 않는다. 과거 G308 세션의 배치 정보는 확인되지 않아 임의로 A/B를 부여하지 않았다.

TX의 IP·PIN 입력과 송신 절차는 그대로다. 강의실 정보는 RX에서 관리하므로 기존 TX 실행기를
사용할 수 있다. **RX 최종 Y 전에 강의실·배치·인원·행동·0명 기준을 다시 확인**한다.

1~4명 수집에서는 다음처럼 입력한다. 기본값을 쓰는 항목은 Enter로 진행한다.

```text
[1-2] 이번 파일의 행동: 0 (앉기→서기→교대 걷기 자동 진행)
[3] 한 동작당 수집 시간(분): 5
[3-1] 반복 횟수: 2 (총 30분)
[4-1] 참가자:자리: P1:Z1 P2:Z2 P3:Z3 (3명 예시)
[4-2] 퇴실·자리 준비 시간(초): 30
[4-3] 안정화 시간(초): 60
```

반복 1회는 15분, 2회는 30분, 3회는 45분이다. 준비·안정화·장비 준비·후처리는 별도다.
한 파일의 **인원수와 강의실·배치는 처음부터 끝까지 고정**한다. 동작이 바뀔 때 파일을
끊거나 TX를 다시 실행하지 않는다. 인원수를 바꿀 때는 파일을 끝내고 RX/TX를 새로 실행한다.

## 같은 CMD 창의 실시간 안내

sudo 인증·카메라 준비 후 **자리 준비/퇴실 → 안정화 → 첫 패킷 대기 → 수집 중 → 기록 마무리 →
저장·검사 → 양쪽 완료 확인** 순서로 안내한다. 준비 중에도 연결·카메라 상태를 점검하며,
준비가 끝나기 전에는 CSI 로거와 TX 송신을 시작하지 않는다.

수집 중에는 같은 터미널 화면이 약 1초마다 갱신된다. 전체 남은 시간, 이번 동작 남은 시간,
현재 해야 할 행동, 다음 행동, 걷기 담당자/방향/정지/교대를 표시한다.
걷기 안내는 5초 단위, 담당자 교대는 60초 단위다. 별도 안내 창을 띄우지 않는다.
터미널 창을 최대화하거나 글자 크기를 키우면 떨어진 자리에서도 보기 쉽다.

```text
CSI 수집 행동 안내
G304 | 배치 A | 3명 | 앉기·서기·걷기 자동 진행
수집 중 3/6구간 | 경과 11:07 / 30:00 | 남은 18:53

지금: P2: W1에서 5초 정지

이번 동작: 교대 걷기 | 남은 03:53 | 1회차
P1: Z1에서 앉기 / P3: Z3에서 앉기
3초 후: P2: W1 → W0로 5초 동안 이동
다음 교대 02:00: P3 (이번 걷기 구간 기준)
```

안내는 첫 유효 세션 UDP 패킷 시각을 기준으로 한다. 행동 전환 때 터미널 알림음을 요청하나,
터미널/데스크톱에서 bell이 꺼져 있으면 소리가 나지 않을 수 있으므로 화면을 기준으로 진행한다.
중단은 Ctrl+C다. 완료·중단 후 화면을 복원하고 결과를 출력하며, Enter를 누를 때 창을 닫는다.

하드웨어 연결이나 파일 생성 없이 안내 화면만 빠르게 미리 보려면 다음을 실행한다.

```bash
python3 tools/csi_activity_guide.py --activity mixed --people 3 --speed 100
```

미리보기는 `DEMO`로 표시하며 실제 CSI·영상·송신·실험 메타데이터를 생성하지 않는다.

## 이전 계획의 행동 규칙

| RX 행동 선택 | 수행 방법 |
|---|---|
| 0명 자동 `empty` | 조작자를 포함해 전원 퇴실. 기기와 가구는 그대로 유지 |
| 0 — 자동 진행 `mixed` (1명 이상 기본값) | 앉기 5분 → 서기 5분 → 교대 걷기 5분, 기본 2회 반복 |
| 1 — 앉기 `sitting` | 지정한 Z 의자에 앉기. 작은 손동작·자세 조절 허용, 자리 이동 없음 |
| 2 — 서기 `standing` | 같은 번호의 발 위치에 서기. 자세 조절 허용, 자리 이동 없음 |
| 3 — 교대 걷기 `walking` | 한 사람만 W0↔W1 2m 왕복. 이동 5초·정지 5초씩 20초 주기. 나머지는 지정 Z에 앉기 |
| 4 — 자세 변경 `sit_stand` | 5분 수집의 첫 150초 앉기, 다음 150초 서기. 인원은 고정 |
| 5 — 자연 활동 `natural` | 고정 행동 프로토콜을 따르지 않는 파일에만 선택 |

걷기 담당은 60초마다 참가자 P 순서대로 교대한다. 5분 동안 1명은 P1을 계속,
2명은 P1/P2/P1/P2/P1, 3명은 P1/P2/P3/P1/P2, 4명은 P1/P2/P3/P4/P1 순서다.
반복 2회차의 걷기는 입력 목록의 두 번째 참가자부터 시작해 첫 담당을 순환한다.
한 파일 안에서는 지정 Z 자리를 바꾸지 않는다. 실제 참가자/자리가 다르면 `[4-1]`에
`P2:Z1 P4:Z2`처럼 입력하며 입력 순서가 첫 회차 걷기 순서다.

오늘은 0명 기준을 먼저 수집한 뒤 1명 30분 → 2명 30분 → 3명 30분 → 4명 30분을
기본 흐름으로 사용한다. 사람이 있는 수집은 합계 2시간이며 0명 시간·준비·저장은 별도다.
하나의 동작만 수집하려면 기존 1~5 선택도 사용할 수 있다.
동작 전환과 걷기 교대의 실제 자리 이동은 영상으로 확인하고, 안정된 동작 구간과 구분해 검수한다.

## 환경 고정과 빈 방 검수

G304의 첫 기준 배치를 A로 기록하고 AP·RX·안테나 높이/방향, TX PC, 의자·책상 위치를
사진과 메모로 남긴다. G308과 같은 수집 절차를 사용하되 두 방의 실제 구조가 같다고 가정하지 않는다.
실제 RF 송신점은 휴대폰 핫스팟/AP이며, 송신 PC는 트래픽 생성기다.
채널 6·2437 MHz, 100 pkt/s·512 B·UDP 5005 등 기존 조건을 유지한다.

인원이 늘어도 의자·가방·기기 위치를 바꾸지 않는다. 조작자도 방 안에 있으면 인원에 포함한다.
파일 사이에 인원을 바꾸고 약 60초 안정 시간을 둔다. 문·창문·팬/에어컨 상태를 기록한다.
가구를 옮기는 B 배치를 진행한다면 이전 계획의 T1 평행 이동 규칙을 적용할 수 있는지 현장에서
확인하고 실제 이동량을 남긴다. 새 배치 B에서는 먼저 B의 0명 기준을 다시 수집한다.
기기를 재설치해 이전 A와 달라지면 `20260917_A2` 같은 새 배치 ID를 쓴다.

RX를 누르고 퇴실한 경우 실제 퇴실 시각을 영상/기록으로 확인하고 그 이전 CSI 구간은 제외한다.
실행기는 퇴실·안정화 카운트다운을 제공하지만 실제 인원을 자동 판독하지는 않는다.
원본 라벨은 계획 인원이므로 카운트다운이 끝나기 전에 실제 퇴실했는지 확인한다.
이전 정적 분석의 처음/끝 30초 제외만으로 모든 출입 구간이 제거됐다고 가정하지 않는다.
실제 방이 비어 있는 안정 구간만 기준 CSI로 사용한다.

## 저장과 이후 평가

저장 경로는 기존 `data/<N>_people/{CSI_DATA,Web_Cam,META_DATA}`를 유지한다.
같은 인원 폴더에 여러 강의실 세션이 있으므로 폴더 이름만으로 방을 판단하지 않는다.

- `meta.json`: `environment.room`, `setup_id`, `empty_reference_session_id`; `label.activity`, `num_people`
- `capture_runtime.json`: 위 장소·배치·기준 값과 실제 수집 완료/중단 상태
- `session_control.json` 및 RX 제어 로그: `collection_context`와 기존 연결·완료 기록
- `activity_segments.json`: 동작 구간·회차·걷기 순서와 첫 UDP 패킷의 실제 시각
- `session_control.json`의 `GUIDE_CUE`: 표시한 지시, 예정 경과 시각, 실제 표시 경과 시각
- `data/structured/<session>/manifest.json`: `environment`로 장소·배치·기준을 전달
- 통합 데이터 manifest: 선택 세션별 `environment` 보존

기존 특징 CSV의 수치 열은 그대로 유지한다. 방·배치 정보는 `session_id`로 manifest와 연결한다.
이 정보는 평가 그룹과 기준 CSI를 고르는 데 사용하며 인원수 정답이나 일정 순서를 추론 입력에 넣지 않는다.

자동 진행 파일의 전체 활동 라벨은 `mixed`다. 각 동작은 `activity_segments.json`에 구분해서
기록하며, 지시한 동작은 영상으로 검증한 정답과 구분한다. 현재 특징 CSV의 `activity`는
파일 단위 `mixed`를 유지한다. CSI 특징 윈도우의 0초는 첫 CSI 레코드이고 행동 안내의 0초는
첫 유효 UDP 패킷이므로, 두 시간축의 대응을 확인하기 전에는 숫자 초만으로 구간을 결합하지 않는다.
변경 경계를 걸치는 윈도우와 실제 자리 이동 구간도 검수 대상이다.

새 방에 0명만 주는 조건을 평가하려면, 예를 들어 G308에서 학습/모델 선택 후 G304의 0명만
환경 보정에 제공하고 G304의 1~4명은 예측을 저장한 다음 별도 정답으로 평가한다.
이 평가에서 G304의 1~4명 데이터를 학습·특징 선택·임계값 조정에 사용하지 않는다.
후속 실험에서는 방의 역할을 바꾸거나 제3의 방을 남겨 같은 조건으로 검증한다.
수집기가 기록하는 `training_candidate`는 후보 표시이며 이 평가의 학습/시험 배정을 뜻하지 않는다.

## G308 기존 데이터 표기 이력

기존 세션 21개(실패 이력 포함)의 위치를 G308로 명시했다. 기존 인원·활동·품질 판정은 유지했고,
메타데이터가 없던 과거 실패 세션에는 위치와 알려진 정보만 담은 최소 메타데이터를 추가했다.
원본 CSI·영상은 이동하거나 수정하지 않았다.
